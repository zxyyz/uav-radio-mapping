# 系统结构

## 最小技术栈

核心使用 Python 3.10+、SQLite 和其 RTree 空间索引。初期不要求 ROS、PostGIS、Docker 或独立前端构建工具。数据库采用 WAL；每个连接启用外键，写入使用事务。包围盒查询利用 RTree 筛选建筑候选，数据库另存双精度范围。

后续 Web 接口拟采用一个轻量 Python 服务，网页读取地图、轨迹和测量数据；先实现增量轮询和按时间分页，再根据需要增加事件流。实时采集的写入路径与回放的读取路径共享数据约定。点云工具、飞行接口和串口接口作为可选模块，不进入核心安装依赖。

## 数据分层

| 层 | 数据 | 存放位置 |
| --- | --- | --- |
| 原始资产 | 点云、影像、AT 原始响应、定位日志 | `data/raw/`，资产表保存路径/哈希/坐标说明 |
| 几何地图 | 区域原点、二维轮廓、激光挤出体、RF 重构地图 | `data/geometry/maps.sqlite3` |
| 观测 | 航次、定位、查询起止时间、服务/邻区观测 | SQLite 对应表；原始日志同时保留 |
| 实验输出 | 重构版本、参数、运行配置、指标、图表 | 数据库运行表和 `data/runs/` |

几何和测量首先共用一个 SQLite 文件，减少部署步骤。点云和视频不存为数据库 BLOB。数据规模或并发需求增加后，再考虑拆分只读资产或更换数据库后端。

## 当前实现

- `init`：建立模式 v1，不创建虚构的实验区域。
- `import-buildings`：事务导入一个 ENU 建筑版本，校验轮廓、标识、原点和高度。
- `buildings`：查询指定地图版本，可按包围盒筛选候选。
- `export-buildings`：输出可再次导入的 ENU JSON。
- `demo`：导入 3 栋明确标注为合成数据的楼房；重复执行保持幂等。
- `status`：查看各表计数和地图版本。

数据库已预留航次、定位、无线观测、小区、基站和算法运行表。当前没有硬件采集适配器、观测上传 API、实时网页、回放播放器或楼高算法实现。

地图版本及区域坐标定义采用不可变方式：重新导入相同版本与内容不追加记录，改变内容必须使用新版本标识。`prior_2d` 的 `height_m` 必须为空；`lidar_truth` 的楼高必须有值。

## 本地工作目录

初次部署使用本机 2T 数据盘上的独立目录。实际绝对路径记录在不提交的 `local/workspace.json` 中。

```text
uav-radio-mapping/
├── src/                   # 开源核心
├── docs/                  # 背景、目标、约定、实验流程
├── tests/
├── data/                  # 以下全部留在本地
│   ├── geometry/          # 实验空库 maps.sqlite3；合成库 demo.sqlite3
│   ├── raw/               # 未来点云、影像和飞行/串口日志
│   ├── legacy/            # 历史测量导出的本地副本
│   ├── derived/           # 导出的模型与中间数据
│   └── runs/              # 实验配置与评估输出
└── local/                 # 本地来源索引、配置与环境记录
```

备份活动数据库时使用 SQLite backup API，或停止写入后整体备份；WAL 模式下不要仅复制活动 `.sqlite3` 主文件。数据库模式升级将使用显式迁移；当前 CLI 拒绝不支持的模式版本。
